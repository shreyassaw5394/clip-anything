# 08-01 — A polished app for normal users — SUMMARY (2026-11-13)

**Shipped (PR #12, branch `app`, commits 878724e d22bc08 + docs):** the tkinter window is replaced by a local web app, the same UI a hosted version can serve later.

- `clip_anything/app/server.py`: stdlib `ThreadingHTTPServer` on 127.0.0.1:<free port>, per-launch token (`?t=` on the page/media/SSE, `Authorization: Bearer` on the JSON API), loopback Host allowlist, Origin must be this server, cross-site `Sec-Fetch-Site` refused on writes, 256 KiB body cap, CSP `default-src 'self'` (no inline code/styles; the native window adds `'unsafe-eval'` because pywebview's bridge needs it). JSON API: caps, jobs (+ SSE `/events` with replay, cancel, open/reveal, delete), `/clips/<job>/<basename>` with byte ranges confined to the job's output folder, setup checks + consent-gated install, native pickers, recent runs (paths only, user data dir).
- `jobs.py`: `JobRequest` → `Options` (count ≤ 20, short/normal/long lengths), one worker thread per job, event log, result shaping (why-picked line from components, post text, peak offset for the poster frame). Re-runs with the same look keep identical clip files (1.3 s cached re-run); a changed look re-renders.
- `pipeline.py`: audio progress events carry `level_db`; `score done` carries the smoothed curve (max-pooled ≤ 720 points) + picked spans, for single files and sessions.
- `static/`: index.html / app.css / app.js, Barlow + Barlow Condensed self-hosted with OFL, paper #f1efe9 / ink / magenta on the data only, radius 0. Screens: drop zone + recent, one divided settings strip, run screen (big bar, stage name, estimate, live curve with popping spans), results grid (real `<video>` with peak-frame poster, hover preview, drag scrub, sound on click, open/reveal/copy/delete with inline confirm, open folder / re-run / export report), setup checklist (plain labels, one-sentence why, "Will run: …" before anything runs), feedback links. Keyboard for everything, focus ring, `aria-live`, reduced motion, works at 1024x640 and 760 wide.
- Entry points: `clip-anything app`, `clip-anything-gui` (`--browser` / `--window` / `--port`), `--selftest` starts the server and fetches the page. `[app]` extra = pywebview (native window, dialogs, dropped-file paths via a Python-side DOM handler → `window.caDrop`).
- Packaging: spec bundles `app/static` and pywebview when installed; `release.yml` installs `--extra app` and can run from a branch (artifacts only). Local macOS build (no captions) 283 MiB; CI with captions: macOS 420 MiB / 163 MiB zip / 178 MiB dmg, Windows 791 MiB / 311 MiB zip; frozen app: `--version`, `--selftest`, headless 3/3 clips in 8.2 s, window stays up.

**Gates:** pytest 134 passed / 3 skipped (7 new in `tests/test_app.py`: foreign Host 403, foreign Origin 403, cross-site 403, no token 401, traversal 404, loopback bind, SSE, ranges, cancel, 409); ruff clean; `scripts/app_e2e.mjs` (Playwright, real server) 31/31; taste-skill lint 0 FAIL; CI: all 6 jobs green on PR #12; screenshots in `.planning/phases/08-polished-app/shots/` (01-home, 03-run, 04-results, 05-setup at 1280x800; 07/08 at 1024x640; 09 at 760).

**Decisions:** pywebview kept (≈ 13 MiB on macOS, Windows build passes CI); browser mode is the fallback and the only mode without eval in the CSP; `force` only when captions/facecam/crop/length/AI changed since the last run on that folder.

**Not verified / next:** a human physical drag-and-drop in the native window and the Windows window itself (WebView2 runtime); hosted mode not built (server is library-shaped: `AppServer(runner=…)`); macOS Intel release job fails on a missing onnxruntime wheel (pre-existing, optional job); first captioned run in the app still downloads the Whisper model (checkbox says so).
