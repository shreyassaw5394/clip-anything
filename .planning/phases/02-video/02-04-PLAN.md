Root cause: scores are file-relative, so a game with one real moment fills the list with its "least boring" menus and cutscenes, which carry music swells + animated transitions (audio×motion agreement).

## Fixes (still game-agnostic)
1. **Absolute bar**: calibrate the score scale across files, not within one: normalise each signal against FIXED reference statistics (median/MAD of the synthetic + COD calibration set stored in config as constants), so a candidate's score means the same thing on every file; `--count` stays a max; a file with one strong moment returns one clip plus the line "1 strong moment found (asked for 10); lower --min-score to get more". Expose `--min-score` (default calibrated so COD returns ~8–10 and Persona ~1–3) and `--count` keeps working as before with `--min-score 0`.
2. **Motion spread / entropy term**: real action moves across the frame; menus, dialogue boxes and cursors move in one small region. Use the existing `cspread` (motion spread) signal: weight agreement by spread so confined motion scores low. Animated menus (the system/config screen) and the shop dialogue must drop.
3. **Text-card and cutscene signals (cheap, generic)**: letterbox bars / flat large regions + slow global pans typical of cutscenes → a mild penalty via "low texture + low spread + steady motion"; never a hard rule. Title cards: first/last 60 s plus very low texture.
4. **Burstiness**: real action has onsets (gunfire, impacts, hits); music swells are smooth. Weight `onset` more inside the agreement term than `loud_rel`/`rms`.
